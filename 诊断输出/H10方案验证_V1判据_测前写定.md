# H10 绕过方案验证 V1：删绑定后单独长采 5 分钟（测前写定）

写于 2026-09-29，V1 采集之前。方案与依据见 `H10启动延迟_结论汇总.md`。
V1 只回答一件事：**删绑定、现场配对的连接能否稳定采满 5 分钟、首帧仍快**。雷达并行（V2）、服务环境（V3）另写判据。

## 条件

- 佩戴、电极湿润，**静坐不动**；手机蓝牙关；Pi WiFi 5 GHz；雷达不运行
- logger 不改（md5 5d3d1cd6，不加诊断参数 = 默认行为），`--duration 300 --connect-timeout 40`，外层 `timeout -k 10 400`
- 每轮前 `bluetoothctl remove`，btmon 全程抓包；3 轮

## 每轮判据（全部满足 = 该轮通过）

| # | 判据 | 通过条件 | 工具 |
|---|---|---|---|
| V1-1 | 现场配对生效 | btsnoop 有 SMP Pairing | `h10_btsnoop_timeline.py` |
| V1-2 | 首帧快 | ECG、ACC 两列都 < 5 s | `h10_start_latency.py` |
| V1-3 | 全程不断 | 日志无 `disconnected` / `connect_attempt_failed`，btsnoop 只有 1 个 Connection Complete | 同上 |
| V1-4 | 第一步判据 1、2、4、5、6 | 按 `H10第一步判据_采集前写定.md` 原阈值，全部通过 | `h10_parse.py` |

**判据 3（RR 与 ECG 逐拍）本次不判定**：其 R 峰检测器 09-28 已证失败、待重写（另案）。
V1 的数据**不得**用来给日后重写的判据 3 定阈值或判通过——那是看了数据再写判据。

## 结论

| 3 轮 | 结论 |
|---|---|
| 都通过 | V1 通过：删绑定方案单独采 5 分钟可用 → 进入 V2（雷达并行） |
| 有轮 V1-1 不满足 | 该轮作废补做（绑定没删掉） |
| 有轮 V1-2 或 V1-3 不满足 | V1 不通过，方案有问题，先查原因 |
| 仅 V1-4 不满足 | 记录，查是方案问题还是佩戴/解码问题，不直接判方案失败 |
