# H10 并入验证 V3（systemd 服务环境 + ABORT 路径，测前写定）

写于 2026-10-09，V3 采集之前，用户已确认。V2 重做与 V2-R 已通过（`H10方案验证_V2重做结果.md`、`H10方案验证_V2R结果.md`）。

V3 只回答一件事：**开机由 systemd（User=pi）拉起、无人登录终端时，H10 链路与 ABORT 路径是否照常**。

## 条件

- 代码不改。测前已核 Pi 上 capture_linux / h10_session / h10_logger / remote_daemon 及 unit 的 md5 与本地一致；服务 enabled、User=pi、KillMode=control-group。
- 配置不改：6000 帧 / 300 s。
- 佩戴 H10，电极湿润，静坐，距雷达 0.5–1 m；手机蓝牙关闭；Pi WiFi 用 5 GHz（RR 热点）。
- 全程不开 ssh 前台采集，只用遥控器操作。我只做只读核查。

## 要验证的三件事

1. 服务环境下删绑定 `bluetoothctl remove` 是否 rc=0（9 月只查过 D-Bus 策略）。
2. 服务环境下 BLE 建连、`timeout` 套壳是否正常（PATH / HOME 与登录 shell 不同；bleak 装在 pi 用户目录）。
3. H10 自成进程组，不在采集程序的进程组里：守护进程退出采集程序后，H10 是否也不残留。

## 流程

| 步 | 操作 | 记录 |
|---|---|---|
| 0 | 雷达、DCA1000、Pi 同时断电，等 10 s，同时上电 | 用户：是否听到「设备就绪」 |
| 1 | 我远程只读核：服务状态、WiFi 频段、雷达 `version` 是否回横幅 | 我 |
| 2 | POWER × 2 启动采集程序 | 用户：语音 |
| 3 | 段 A：ENTER × 2，采集开始约 60 s 后按 ESC 中止 | 用户：语音 |
| 4 | 段 B：ENTER × 2，正常采满 5 分钟 | 用户：语音 |
| 5 | POWER × 2 退出采集程序 | 用户：语音；我远程核残留 |

第 1 步如果雷达不回横幅：记为「冷启动雷达零回显」复现，归入单独的待查项，**不算 V3 不通过**。用户重上雷达电后，从第 2 步继续。

## 判据

| # | 判据 | 通过条件 |
|---|---|---|
| V3-1 | 开机自启 | 上电后 `radar-remote` 为 active，播放了 `daemon_ready.wav`（开机语音；用户改过内容，实际听到的是「守护进程已启动」，测前写成「设备就绪」是我写错了文字，判据对象不变）；POWER 拉起的 capture_linux 与 h10_logger 进程用户都是 pi |
| V3-2 | 正常段 B | `h10_v2_check.py --redo` 判 V2-1..V2-7 全过（含删绑定 rc=0、首帧 ECG/ACC < 5 s） |
| V3-3 | 中止段 A 的雷达部分 | 有 `ABORT_Cow_*` 目录；`verdict=ABORTED`；`sensor_stop_sent=yes`；听到「已中止」 |
| V3-4 | 中止段 A 的 H10 部分 | 段目录里恰好 1 个 h10 日志 + 1 个 `.stdout.txt`；`h10_exit=正常退出`；日志里建连前有 `bond_remove rc=0`；`_h10_staging` 为空、本段时间内无 H10_ORPHAN 新文件 |
| V3-5 | 中止后可继续 | 段 B 能正常开采，没有被残留检查挡住 |
| V3-6 | 退出后无残留 | POWER 退出后，`capture_linux`、`h10_logger`、`DCA1000EVM_CLI_Record`、`tcpdump` 均不存在；`radar-remote` 仍为 active |
| V3-7 | 语音 | 段 A、段 B 开头各听到一次「心率带已连接」，全程没有「断开 / 重连 / 未连接」 |

段 A 不跑七项判据（ABORT 设计如此），也不判判据 3。段 B 的判据 3 按惯例单列，不影响 V3 结论。

## 结论

| 结果 | 处理 |
|---|---|
| 全部通过 | H10 并入主流程验证完成。之后用户把配置改回 600 帧，服务保持 enabled |
| V3-2 / V3-4 因删绑定 rc≠0 或首帧 ≥ 5 s 不过 | 服务环境权限问题。查 journal 与 `.stdout.txt`；备用方案按 `h10-30s-start-delay-concluded`（只清 BlueZ GATT 缓存）另写判据 |
| V3-6 有 h10_logger 残留 | 生命周期问题，修代码后重做 V3 |
| 其他不过 | 记下原因，报告用户，不放宽判据 |

## 这套验证证明不了什么

- 只覆盖一次冷启动。上电时序类问题（如 13:35 的雷达零回显）需要多次冷启动才能看出频率。
- 只覆盖人体、静坐、室内、手机热点 5G。牛场的网络、距离和遮挡另测。
